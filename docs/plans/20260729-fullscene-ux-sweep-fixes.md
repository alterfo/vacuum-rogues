# Full-Scene UX Sweep Fixes

## Overview

A full-scene AI-vision UX sweep (2026-07-29, `docs/playtests/20260729-fullscene-ai-vision-ux-sweep.md`)
ran two Playwright discovery specs (`e2e/letsplay-discovery.spec.ts`,
`e2e/visual-sweep-task17.spec.ts`) to capture ~65 screenshots across every
player-facing scene, then had 4 parallel `ux-reviewer` agents review them.
That surfaced 25 findings (9 significant, 10 moderate, 6 minor). A follow-up
Explore pass source-mapped every significant/moderate finding to exact
file:line locations (table below) and, in the process, **refuted 3 of the 9
significant findings** as stale-screenshot artifacts rather than live bugs —
the same failure mode the same-day precedent
(`docs/plans/completed/20260729-ux-review-fixes.md`) hit 4 times:

- **Combat "two visual languages" (hex-grid vs. orbital view)** — `CombatScene.ts`
  (the hex-grid board) was deleted in commit `df0f4fbe`; combat is real-time
  in-flight only today. The hex-grid screenshots are stale, pre-deletion
  captures never regenerated by either current sweep.
- **Locale-inconsistent combat title (EN "TACTICAL COMBAT" vs RU)** — both
  strings belonged to the same deleted `CombatScene.ts`; no such string exists
  in current `src/`.
- **Star-map inconsistency (EN "SECTOR MAP" header capture)** — `star-map.png`
  predates the rebrand commit that removed the English title; the current
  `StarMapScene` title is unconditionally `"КАРТА ГАЛАКТИКИ"`.

These three are **closed with no code change** — Task 1 re-confirms them
live (cheap, since the Explore evidence is already strong: a deleted file and
two git-log-dated screenshots) before the plan moves on. Four more items from
the sweep's "needs live verification" section (faction-select difficulty
panel, onboarding-tooltip re-trigger, ship-view content, station.png bare
panel) were **not** resolved by the Explore pass and still need a real
click-through check — also folded into Task 1.

The remaining **16 confirmed real findings** (6 significant + 9 moderate + 1
reclassified) get one task each, ordered by severity/value. The 6 minor
findings get lighter-weight tasks grouped by area. Station's flat-gradient
backdrop (finding "Station backdrop art") is **already the documented,
deliberate interim fix** from the prior pass (real art needs external ComfyUI
generation) — no new task, just a Post-Completion note.

## Development Approach

- **Testing approach: regression-first (TDD)**, per root `CLAUDE.md`'s Bug
  Fixing Process — red test first (unit test for pure logic/text-building
  bugs; real-engine playtest test for wiring/scene bugs per the three-tier
  table), fix until green, then a real screenshot re-capture for any visual
  change (text-level green alone is not evidence for a visual bug).
- **Blast-radius discipline**: before editing any symbol above, run
  `gitnexus impact <Symbol>` (or `vacuum find_symbol` to read the body first)
  per root `CLAUDE.md`'s "Before Every Code Change" section — several of
  these files (`combatExecution.ts`, `NpcShipManager.ts`) have known-tricky
  freeze/pause interactions documented in memory (isPaused/isFrozen gotchas);
  read the surrounding freeze-gate logic fully before touching it.
- Complete each task fully before moving to the next; run tests after each
  change; all tests must pass before starting the next task.
- **PRIMARY rule: never modify or weaken existing test assertions** — the
  suite is known-good; only add new tests.
- Update this plan file when scope changes during implementation.

## Testing Strategy

- **Unit tests**: required for every task — pure logic/text-building fixes
  (population resolution, tag spacing, label text, news dedup) get a unit
  test in `src/tests/`.
- **Real-engine playtest tests**: required for wiring/scene bugs (combat
  status-bar drawing during PLANNING, NPC tooltip wiring, contact panel
  redundant-line removal) — boots the real `GameEngine`, per the three-tier
  table in root `CLAUDE.md`.
- **E2E/visual verification**: any visual-layout fix (job-board spacing,
  faction-select grid, game-over layout, planet header scrim) needs a
  screenshot re-capture via the existing sweeps or a targeted Playwright spec
  before being called done — green tests alone are not sufficient evidence
  for a visual bug per root `CLAUDE.md`.
