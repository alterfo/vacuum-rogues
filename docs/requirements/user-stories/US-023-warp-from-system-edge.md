# US-023: Гиперпрыжок только с края системы

> Эпик: [EPIC-004](../epics/EPIC-004-grand-system-radar-background.md) · Канон: SOURCE-OF-TRUTH §3

## User Story
**Как** игрок
**Хочу** чтобы перед прыжком в другую систему корабль долетал до края текущей
**Чтобы** гиперпрыжок происходил на рубеже системы, как в оригинале

## Статус: Done

## Acceptance Criteria

```gherkin
Scenario: Прыжок через край системы
  Given я в полёте в системе
  When я открываю карту звёзд и выбираю систему для прыжка
  Then строится маршрут к краю системы (в направлении цели)
  And корабль летит к краю (дни капают во время полёта)
  When корабль достигает границы системы
  Then происходит гиперпрыжок (списывается топливо, смена системы)
  And в новой системе корабль появляется на границе со стороны origin

Scenario: Недостаточно топлива
  Given у меня недостаточно топлива для прыжка
  Then прыжок нельзя инициировать с карты
```

## Реализация (как сделано)
1. **StarMapScene.performWarpJump**: подтверждение прыжка больше НЕ списывает
   топливо и НЕ меняет систему. Проверяет топливо, вычисляет `exitVector`
   (направление от текущей системы к цели) и возвращает в `SPACE_FLIGHT`
   текущей системы с контекстом
   `pendingWarp: { targetSystemId, fuelCost, exitVector }`.
2. **SpaceFlightScene**: при `pendingWarp` корабль спавнится у центра системы и
   авто-прокладывает маршрут к точке края `center + exitVector *
   SYSTEM_BOUNDARY_RADIUS` (`setTarget` + линия маршрута). Дни капают во время
   полёта как обычно. Навигационные клики заблокированы (корабль закоммичен на
   прыжок); пан/зум камеры работают.
3. На прибытии у края (`updateShip` → arrival) вызывается `performWarp`: списать
   топливо, `currentSystemId = target`, `revealSystemAndNeighbors`, авто-сейв,
   `transitionTo(SPACE_FLIGHT)` нового мира с `entryVector = -exitVector`
   (появление со стороны origin). Флаг `warpInProgress` защищает от повторного
   срабатывания на время перехода сцены.
