# Вакуумные Пройдохи

**Вакуумные Пройдохи** — браузерная космическая RPG/стратегия с открытым миром,
локальными ONNX-моделями для генерации диалогов и тактического ИИ.

## Быстрый старт

### Предварительные требования

- Node.js 20+
- npm или pnpm

### Установка и запуск

```bash
# Установка зависимостей
npm install

# Запуск dev-сервера
npm run dev

# Сборка для production
npm run build

# Предпросмотр production-сборки
npm run preview

# Запуск тестов
npm test

# Проверка линтером
npm run lint
```

## Архитектура

### Технологический стек

- **TypeScript 5.4+** — строгая типизация
- **Vite 5.2+** — сборка и dev-сервер
- **PixiJS 8.0+** — рендеринг (WebGL / Canvas2D)
- **onnxruntime-web 1.17+** — локальный ONNX-инференс
- **IndexedDB** — кэширование моделей и сохранений
- **Web Workers** — параллельный инференс

### Ключевые компоненты

```
src/
  main.ts              — Точка входа
  systems/GameEngine.ts — Центральный движок
  presentation/
    SpaceFlightScene.ts — Сцена полёта с кораблём

    MainMenuScene.ts    — Главное меню
  ai/
    ONNXModelRegistry.ts — Регистрация и загрузка ONNX-моделей
    inference.worker.ts  — Web Worker для инференса
  data/
    SaveManager.ts       — Управление сохранениями
```

## Игровой процесс

### Фракции

| Фракция     | Специализация                        |
| ----------- | ------------------------------------ |
| Окраинники  | Торговля, ремонт, надёжность         |
| Бастионы    | Военные технологии, броня            |
| Синдикат    | Контрабанда, скрытность, скорость    |
| Парадоксы   | Уникальные модули, непредсказуемость |
| Прогрессоры | Технологии, наука, дроны             |

### Основные механики

- 🚀 Свободные перелёты между звёздными системами
- 💰 Торговля товарами с динамическими ценами
- ⚔️ Бои в реальном времени с активной паузой — при обстреле игра замирает и даёт выбрать цель и оружие (стиль Space Rangers / FTL)
- 📜 Квесты с ветвящимися сюжетами
- 🌍 Живая галактика — NPC живут независимо от игрока
- 🏦 Галактический банк (АБС) — счета, выписки, вклады и кредиты, наглядная визуализация двойной записи и шины
- 🎚️ Режимы сложности (выбор при старте новой игры):
  - **Бог** — корабль не гибнет: при нуле прочности он остаётся жив, но «выведен из строя» (downed) — не может стрелять и совершать гиперпрыжок, пока его не отремонтируют выше порога прочности
  - **Средний** — стандартная сложность (поведение по умолчанию)
  - **Сложный** — больше пиратов и Сверхразума (больше враждебных систем) и крупнее гарнизоны
- 💀 Гибель корабля (в режимах Средний/Сложный) — экран «Корабль уничтожен» с откатом к последнему взлёту (автосейв в слот «auto») или началом новой игры (в режиме «Бог» корабль не уничтожается)
- 🆘 Системное меню в полёте — кнопка **[МЕНЮ]** в левом верхнем углу всегда доступна: «Загрузить сохранение» (откат к автосейву с подтверждением) или «В главное меню» — выход из любого тупика (обстрелян, прочность < 30%, двигатели остановлены, нет кредитов)

### Управление

- **Пробел** — выполнить проложенный маршрут (запустить ход в полёте)
- **Enter** — подтвердить основное действие в окне (например, первый ответ в диалоге)
- **Esc** — закрыть окно / отменить проложенный маршрут
- **Двойной клик** по системе на карте галактики — прыжок (одиночный клик — информация о системе)
- **J** — журнал заданий, **I** — инвентарь
- **[МЕНЮ]** (кнопка в левом верхнем углу) — системное меню в полёте: загрузить сохранение / выйти в главное меню

### Добавление новой сцены

1. Создать класс, наследующий `GameScene`
2. Реализовать методы `initialize()`, `update()`, `destroy()`
3. Добавить `case` в `src/core/services/SceneFactory.ts`
4. Добавить `SceneType` в `src/types/index.ts`

### Интеграция ONNX-модели

1. Добавить конфигурацию в `src/ai/ModelManifest.ts`
2. Создать адаптер (напр., `T5DialogueAdapter`)
3. Использовать через `ONNXModelRegistry`

## Деплой

### GitHub Pages (текущий прод)

Push в `master` запускает `.github/workflows/notify-alterfo.yml`, который шлёт
`repository_dispatch` на `alterfo/alterfo.github.io-src`; тот фетчит свежий
`master` этого репозитория и пересобирает GitHub Pages — ручной bump не нужен.

### Ручной деплой

```bash
npm run build
# Загрузить dist/ на любой статический хостинг
```

## Переменные окружения (для CI/CD)

- `BLOG_DISPATCH_TOKEN` — секрет этого репозитория (PAT): создаёт
  `repository_dispatch` на `alterfo/alterfo.github.io-src` для пересборки прода
  (см. `.github/workflows/notify-alterfo.yml`).
- `GITHUB_SHA` — выставляется GitHub Actions автоматически; используется как
  запасной источник git-SHA для диагностики в форме отзыва (основной — локальный
  `git rev-parse` сборочного чекаута; см. `vite.config.ts`).
