# Local ralphex task-execution prompt override for SpaceRangers.
#
# WHY THIS FILE EXISTS (Task 5 of docs/plans/20260614-ai-dev-tooling.md):
# ralphex starts every task iteration with a cold context. Without guidance the
# model re-reads 4-5 whole source files just to remember what the task touches,
# which burns context budget and invites lockstep-edit mistakes. This override
# prepends a "vacuum MCP-first orientation" preamble to the default ralphex task
# prompt so the model locates symbols by line number BEFORE reading files, and
# reads only the **Files:** the task lists.
#
# HOW RALPHEX LOADS THIS:
# ralphex resolves task.txt with the chain local (.ralphex/prompts/) -> global
# (~/.config/ralphex/prompts/) -> embedded default. A local file fully REPLACES
# the default (it does not merge), so the verbatim default body is reproduced
# below the preamble. ralphex strips this contiguous leading "#" comment block
# (2+ lines) before sending the prompt to the model, so these notes never reach
# the model -- they are for human maintainers only.
#
# EXPECTED BEHAVIOR (manual verification, since ralphex runtime is not unit-testable):
# In .ralphex/progress/progress-*.txt for a run that uses this prompt, the first
# tool calls of an iteration should be vacuum MCP calls (find_symbol /
# get_architecture / get_scene_info) BEFORE any Read of a whole source file. If
# the task lists a **Files:** block, only those files should be read.
#
# KEEP IN SYNC: if ralphex's bundled defaults/prompts/task.txt changes in a future
# release, re-extract it and re-apply the preamble (see ralphex-update skill).

BEFORE reading any source files, orient with the `vacuum` MCP server (one tool call beats five greps):
1. Call `find_symbol` for each key type/class/interface the task mentions (e.g. QuestType, NpcRole) to get an exact `file:line` instead of grepping.
2. Call `get_architecture` to confirm which layer owns the change and which lockstep files (schema, migration, SceneFactory) must move together.
3. For a scene task, call `get_scene_info` to see lifecycle line numbers without reading the whole 1,000+ line scene file. For balance questions call `get_balance_constants`. To find a file's tests call `find_tests_for`.
4. Then read ONLY the line ranges you need around those line numbers — not entire files.
5. If the current task has a `**Files:**` section, read only those files (optionally run `tools/context-inject.sh {{PLAN_FILE}}` to print the active task's Files block and on-disk status). Do not scan the whole codebase.

This orientation step keeps per-task context small and prevents missing one of the lockstep files. After it, proceed with the task exactly as described below.

STANDING RULES FOR THIS PROJECT (enforce on every iteration without exception):

1. BLAST RADIUS FIRST. Before editing any function, class, or method call `gitnexus impact({target:"SymbolName",direction:"upstream"})` and report the direct callers. Skip only for brand-new files with no callers yet.

2. NEVER TOUCH EXISTING TEST ASSERTIONS. The test suite is known-good. You may add new tests and new test files, but never weaken, delete, or change the meaning of an existing `expect(...)` assertion. If a change makes an existing test red, that is a root-cause signal — diagnose and fix the code, not the test.

3. VALIDATE WITH: `npm test -- --run` (unit, ~15 s), `npm run lint`, `npx tsc --noEmit`. Do NOT use bare `npm test` (that opens watch mode). All three must be green before marking a task done.

4. LOCKSTEP EDITS — never do one without the others:
   - New domain field (src/types/ or src/domain/)  →  src/validation/schemas.ts  +  src/data/MigrationPipeline.ts (if old saves need defaulting)
   - New UI string (player-facing text)  →  add key to BOTH src/i18n/ru.ts AND src/i18n/en.ts; render through t("key") — never an inline Cyrillic literal
   - New scene  →  SceneType enum, SceneFactory case, contextDependentScenes if needed

5. COMMIT HYGIENE. Commit message subject ≤ 100 characters (commitlint enforces this). Never pass --no-verify. If a pre-commit hook fails, fix the underlying issue.

6. SpaceFlightScene.ts LINE GUARD. After any edit to src/presentation/SpaceFlightScene.ts run `wc -l src/presentation/SpaceFlightScene.ts` — must be ≤ 1898. If over, extract to a helper before committing.

7. NO DIRECT CREDIT MUTATION. Credits move through economy.ts helpers (adjustPlayerCredits / payTribute / transfer) — never `player.credits +=`.
