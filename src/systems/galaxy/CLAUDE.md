# Galaxy System Conventions

## Galaxy Balance

Completed `20260611-overmind-equilibrium-balance`:
- `Galaxy` tracks two hostile factions separately: `overmindSystems: string[]` (loss-condition) and `pirateSystems: string[]` (difficulty/narrative). `addPirateSystem` / `addOvermindSystem` are mutually exclusive (each removes from the other list). **Never call `removeOvermindSystem`/`removePirateSystem` directly from outside `Galaxy`** — use `galaxy.tryLiberate(systemId)` which handles both types and emits the `SYSTEM_LIBERATED` news event.
- **Loss gate (superseded by the endgame arc)**: the loss condition is now owned by the spread state machine — `advanceOvermind` (`src/systems/overmind/`) derives `status: "lost"` from the post-capture share (past grace, on a big-enough galaxy), and `GameEngine.advanceGalaxyDay` routes that to the defeat screen. The legacy `galaxy.isOvermindVictory(...)` / `isOvermindMajority()` helpers (and `GAME_BALANCE.OVERMIND_LOSS_GRACE_DAYS` / `OVERMIND_LOSS_MIN_SYSTEMS`) are **retained for tests only** — their EOD caller was removed by `20260625-overmind-endgame-living-galaxy`. Do **not** wire a new loss check onto them; extend the arc machine instead.
- **Self-balancing tick**: `OvermindBalance.ts` exports `stepOwnershipTick` — a pure function (no side effects, no GameEngine coupling). `GalaxyStatusIndicator.ts` exports `computeGalaxyThreat` — thresholds: safe <20%, caution 20–35%, warning 35–45% (`GAME_BALANCE.OVERMIND_WARNING_THRESHOLD`), critical ≥45%. Both modules are pure; keep them that way.
- **The endgame arc owns the Overmind front — pass `freezeOvermind`** (`20260625-overmind-endgame-living-galaxy`, Task 5). Once the Overmind holds any territory, `GameEngine` calls `stepOwnershipTick` with `config.freezeOvermind: true` so the equilibrium **only churns pirates** (no Overmind capture, no Overmind recapture/liberation) — the EOD spread machine (`advanceOvermind`, `src/systems/overmind/`) + the player are the sole authorities on the Overmind front. This is load-bearing: without it the equilibrium's ~25% feedback ceiling **capped the arc below its loss line** (defeat unreachable) **and** could **liberate the Overmind core** (a spurious "core broken" win) on the 5-day cadence. `freezeOvermind` defaults `false`, so the pure-function tests/contract are unchanged. **Note** the arc reads the warp graph as **undirected** (`frontierSystems`) because ~25% of links are one-way; `stepOwnershipTick` itself still scans directed borders — fine for pirate churn, but don't assume it sees one-way Overmind edges.
- **Hostile-system combat difficulty**: `OVERMIND_COMBAT_HP_MULT` / `OVERMIND_COMBAT_DAMAGE_MULT` (`balance.ts`) once scaled the hex `CombatScene` when `isHostileSystem: true`. Since the `20260623-space-combat-realtime-fix-remove-hex` plan **all** combat is real-time in-flight — the hex `CombatScene` and `SceneType.COMBAT` were **deleted**, so every fight (regular NPCs, the OVERMIND-core boss, former text-quest encounters) resolves via `CombatModule` (real-time auto-fire), which does **not** apply these multipliers. The two constants are **kept** in `balance.ts` (still asserted by `combatLiberation.test.ts`) but have **no production consumer**. **Known limitation / follow-up**: porting the hostile-system difficulty scaling into the in-flight `CombatModule` is still unimplemented — overmind/pirate-system NPC fights are currently no harder than neutral ones.
- **`NewsEvent` type convention**: any new `NewsEvent.type` literal must also be added to `NEWS_TYPE_LABEL` and `NEWS_TYPE_COLOR` maps in `InfoCenterScene.ts`, and to the Zod enum in `schemas.ts`. Current types: `SYSTEM_LIBERATED`, `SYSTEM_CAPTURED`, `LIBERATION_CAMPAIGN`, `OVERMIND_EXPANSION`, `PIRATE_SURGE`, `NPC_QUEST_COMPLETE`, `PIRATE_ATTACK`, `MARKET_SHIFT`, `TRADE_OPPORTUNITY` — see `src/types/index.ts` for the full union. `LIBERATION_CAMPAIGN` carries optional `targetSystemId` / `stagingSystemId` / `liberationDate` fields; `TRADE_OPPORTUNITY` carries optional `resource` / `fromSystemId` / `toSystemId` / `marginPct` fields. Note an *expiring* rumor emits a `MARKET_SHIFT` ("акция закончилась"), not a `TRADE_OPPORTUNITY` — only *opening* a rumor uses `TRADE_OPPORTUNITY`.
- **NPC persistent world position / tracked movement** (`20260619-npc-ship-persistence-consistency`, save **v23→v24**): `NpcShip` carries a persisted `worldX`/`worldY` (offset from the system star centre, `null` until first placed), mutated **only** via `setWorldPosition` — so a system's ships keep their spots across scene transitions and save/load instead of re-scattering with `Math.random()` on every entry. Schema lockstep: `NpcShipSchema` (`worldX`/`worldY` `z.number().nullable().default(null)`) + `MigrationPipeline` 23→24, which seeds old-save ships a deterministic offset via `deterministicNpcOffset(galaxyId, npcId)` (`src/systems/npc/npcPlacement.ts`). The migration is **load-bearing, not redundant**: `advanceTrackedPositions` skips ships with a null position, and the only other placement path is the flight scene (player-visited systems only), so without the migration an old save's off-screen ships would never get a position and never move. `NpcSimulator.tick` calls `advanceTrackedPositions`: each placed, present (non-DEAD/non-TRAVELING) ship is rotated one deterministic orbit step (`npcOrbitStep`/`advanceNpcOrbit`) — radius-preserving, **no main-RNG consumption** (the deterministic stream other systems/tests depend on stays bit-identical). `deterministicNpcOffset` is keyed by galaxy seed + ship id (**system-independent**), so a ship migrating between systems keeps a valid in-band offset. Guarded by `src/tests/npc/{npcShipPosition,deterministicPlacement,trackedMovement,starMapRoundTrip}.test.ts`.
- **Hostile systems / garrisons / liberation** (`NpcSimulator`): a captured system holds a standing garrison (Overmind = `OVERMIND` faction + `PATROL` role; pirate = `PIRATE` role), spawned by `ensureGarrison` and held in place (excluded from the wandering streams). Garrison/capture-fleet ships are tracked in in-memory sets (`garrisonIds`, `captureFleetIds`) that reset on load and rebuild on the next tick — never persisted. Capture needs ≥ `CAPTURE_FLEET_MIN` HUNT ships arriving with no defenders left. Liberation fires after `LIBERATION_CLEAR_DAYS` of zero garrison presence via a `gameDays`-based `liberationCountdown` `Map` (save-safe: rebuilds on load). When a system is freed by **any** path (convoy, DEFENSE quest, `tryLiberate`, countdown), `resolveLiberationDetection` despawns any leftover frozen garrison ships. `NpcShip.hostile` (`markHostile()` / `isAggressive()`) is the single source of truth for **reactive** aggression (a ship attacked turns hostile); attacking one neutral propagates hostility to same-faction in-system neighbours.
- **Faction hostility matrix** (`20260620-faction-hostility-pirate-overmind-ai`): `src/systems/npc/factionHostility.ts` is the single source of truth for **innate** who-is-hostile-to-whom (the enmity counterpart to reactive `NpcShip.hostile`). `isHostile(attacker, target, ctx)` / `shipsAreHostile(a, b, ctx)` over `FactionKind` (`overmind | pirate | trader | ranger | patrol | player`): Overmind is hostile to all non-Overmind (indiscriminate, expansion-driven); pirates prey on traders + the player, fight rangers/patrols, are mutual enemies of the Overmind, never attack other pirates, and **exempt a good-rep player** (`ctx.pirateRep >= GOOD_PIRATE_REP_THRESHOLD`, shared with the landing-gating plan); rangers/patrols hunt pirates + Overmind; traders/player are innate non-aggressors. Helpers: `selectPirateTarget` (weakest hostile prey, combat-strength weighted), `pirateCoordination` (pack in pirate-captured systems via `galaxy.isPirateSystem`, solo elsewhere), `mutuallyHostile` + `overmindCombatTargets` (spontaneous NPC-vs-NPC brawls). Both the off-screen sim (`NpcSimulator.resolveGarrisonOffscreenCombat` / `resolveCrossFactionCombat` / pack-vs-solo raids) and in-flight combat (`NpcShipManager.resolveNpcVsNpcCombat`) consult it — **never re-derive `role === PIRATE` / `faction === OVERMIND` relations inline.** Pure (no RNG/I/O). **Off-screen reachability note:** `resolveCrossFactionCombat` resolves *mutual* damage only between **wandering** (non-garrison, non-capture-fleet) ships; since every live Overmind ship is spawned into `garrisonIds`/`captureFleetIds`, in practice off-screen Overmind↔pirate combat runs through the one-directional `resolveGarrisonOffscreenCombat` (garrison hits intruders, takes no erosive retaliation — the standing-garrison persistence invariant). The *mutual* path is reachable in-flight, where the manager has no garrison concept.

## Market Population

Completed `20260616-populate-planet-markets`:
- Every planet's market is seeded at generation by `marketSeeding.ts::seedMarket(economyType, planetId)` → `{ availableResources, supplyVector, demandVector }`, applied via `planet.market.populate(...)`. It is **pure and deterministic** — seeded from `planetId` via `SeededRNG("market:"+planetId)`, never `Math.random` — so saves/replays reproduce identical vectors. Determinism is load-bearing: a non-deterministic seed would desync price drift across save/load.
- Wired in `GalaxySimulator` at **two** sites: the main generation loop (≈L89) and the faction-home override in `assignFactionHomeSystems` (≈L632), which **re-seeds under the override economy** — the override wins for faction-home planets. Any new place that sets `planet.market.economyType` must also call `populate(seedMarket(...))`, or the market falls back to the empty stub (`new Market([], [], [])`) and the whole dynamic-pricing layer goes inert.
- **Loaded saves — known gap:** population runs only during fresh generation. Saves created *before* this feature carry empty stub markets, and the load path (`GameEngine.rehydrateLoadedState`) only restores prototypes — it does **not** re-seed. On those saves the dynamic-pricing layer stays inert. No schema migration is needed (no persisted *field* was added; the arrays already existed, just empty), but a load-time re-seed of empty markets is the follow-up — wire it into `rehydrateLoadedState` after the prototype loop (skip markets with `availableResources.length > 0`, seed via `seedMarket(market.economyType ?? system.economyType, planet.id)`).
- Every planet trades the **full** `ResourceType` catalogue; cross-planet spreads come from economy-biased supply/demand, not from which goods exist. Vectors are clamped `> 0` (pricing divides by supply).
- `seedMarket` derives bias from `economyBaseline()` *inverse* (cheap baseline ⇒ abundant supply, low demand) so the dynamic vectors agree in direction with the static `econMult` in `TradeSystem.getMarketPrice()`. `economyType` is written back on re-seed to keep static and dynamic in sync.
- `Market.priceMultipliers` is the **dynamic** layer only (trade impact + events); `advanceMarketDay` mean-reverts it toward **1.0, not the economy baseline** — the baseline is already applied separately as `econMult` in pricing, so reverting toward it too would double-apply the economy effect and widen every arbitrage route instead of closing it.
- **Persistence caveat:** `StarSystemSchema` (`schemas.ts`) has no `planets`/market sub-schema, so markets are **not** Zod-validated; they persist as raw JSON through `SaveStateSerializer`'s `JSON.stringify`/`JSON.parse`. Don't assume `GalaxySchema.parse` guards market structure — it strips `planets` entirely.
- **Two divergent price formulas (follow-up):** populating markets *activates* a pre-existing inconsistency. The player-facing trade screen prices via `TradeSystem.getMarketPrice` (per-resource `basePrices`, regressor, reputation, `econMult`, drift multiplier, clamped to `[base×0.3, base×3.0]`), but `Market.getPrice` — used by `GalacticRegistry.indexMarkets` (the info-center "[РЫНОК] best price" listings the player reads) **and** `NpcSimulator.pickTraderCargo` — uses raw `round(demand/supply × 100 × mult)` with **no** base price, econMult, or clamp. Before this plan, production markets were empty so these listings showed nothing; now they show numbers that don't match (and can rank a different "best" planet than) what the trade screen actually charges. Unifying them needs a player-independent reference price (the registry has no `Player`, which `getMarketPrice` requires). **Update (`20260616-living-trade-economy-rumors`):** that reference price now exists — `TradeSystem.referenceMarketPrice(planet, resource)` mirrors `getMarketPrice` with reputation/rank/player flags zeroed — but it is currently consumed **only** by the route scanner. `GalacticRegistry.indexMarkets` and `NpcSimulator.pickTraderCargo` still call raw `Market.getPrice`, so the divergence the player sees in the info-center "[РЫНОК]" listings is unchanged. Re-pointing those two callers at `referenceMarketPrice` is the remaining cleanup.

## Trade Rumors (living-trade-economy)

Completed `20260616-living-trade-economy-rumors` — a self-balancing "trade-rush" loop in `src/systems/trade/`:
- **`RouteScanner.scanTradeRoutes(galaxy, priceFn, opts)`** is a pure ranking function → `RouteCandidate[]` (cross-system pairs only, sorted by margin desc, deterministic id tie-break). It takes a neutral `priceFn` (wire `TradeSystem.referenceMarketPrice`), never a `Player`.
- **`RumorDirector.updateRumors(galaxy, scanFn, day, cfg)`** advances the rumor lifecycle: re-score active rumors from a fresh scan → expire those at/below `rumorMarginExpire` (emit `MARKET_SHIFT` "акция закончилась") → open the most-profitable un-active routes above `rumorMarginOpen` up to `rumorMaxActive` (emit `TRADE_OPPORTUNITY`). The open/expire thresholds form a **hysteresis band** so rumors can't flap on daily drift. The director is decoupled from the scan via a `RouteScanFn` closure (testable without a galaxy).
- **Daily-tick ordering contract** (`GameEngine.advanceGalaxyDay`): NPC tick → global events → **market drift → scan → `updateRumors`**, guarded by `marketSystemCount >= 2` (no cross-system route can exist below that).
- **Convergence** uses the SAME persistent `applyMarketTradeImpact` lever as the player: a diverting NPC trader raises the rumor *source* in `NpcSimulator.pickTraderGoal` (buy leg) and lowers the *destination* in `simulateTraderTrade` on arrival (sell leg); NPC magnitude is `0.5×` the player's per-unit impact, capped per trade. Drift mean-reverts toward 1.0, so closed routes relax and can re-open later.
- **NPC reaction** (`rumorReactionChance`, exported) `= clamp(rumorNpcBaseChance + rumorNpcMarginScale × max(0, marginPct − rumorMarginExpire), 0, rumorNpcMaxChance)` — anchored to the margin *above* expiry so the pull tapers to ~base as the spread closes. Only `TRADER` NPCs react, and `rng` is drawn **only** when a reachable rumor exists (the no-rumor stream stays bit-identical).
- **Persistence:** `Galaxy.activeRumors: RouteRumor[]` is a method-less value type, JSON-serialized like the rest of the galaxy. `RouteRumorSchema` + `GalaxySchema.activeRumors` mirror it (default `[]` for old saves). `RouteRumor` lives in the domain layer and avoids the upward import by structurally matching the systems-layer `RouteCandidate` via `RouteLike = Omit<RouteRumor, "id"|"createdDay"|"lastMarginPct">`. **Load caveat:** `setPrototypeOf` does not run the `activeRumors = []` field initializer and SaveManager returns the raw (un-defaulted) parsed object, so `rehydrateLoadedState` must coerce a missing `activeRumors` back to `[]` (regression: `GameEngine.rumor-rehydration.test.ts`).
