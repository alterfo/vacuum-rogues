# US-024: Клики в модалках/диалогах не проваливаются в карту

> Кросс-срезовая UI/input-история (баг). Канон: SOURCE-OF-TRUTH §3.
> Связано с CLAUDE.md → PixiJS Event Handling Rules 1–2.

## User Story
**Как** игрок
**Хочу** чтобы клики по модалкам и кнопкам диалогов не «протекали» в карту
**Чтобы** случайно не строился маршрут при закрытии окна/диалога

## Статус: Planned (баг, не исправлено)

## Воспроизведение (наблюдаемое поведение)
1. Открываю модалку на звёздной карте и кликаю в ней →
   клик дополнительно обрабатывается картой.
2. Выхожу из диалога с губернатором →
   срабатывает клик по карте и **строится маршрут** в `SpaceFlightScene`.

→ Этот клик планетарной/звёздной картой обрабатываться **не должен**.

## Acceptance Criteria

```gherkin
Scenario: Клик по модалке звёздной карты не доходит до карты
  Given открыта модалка (подтверждение прыжка и т.п.)
  When я кликаю внутри модалки
  Then обрабатывается только модалка
  And карта НЕ выделяет систему и НЕ строит маршрут

Scenario: Выход из диалога не строит маршрут
  Given я в диалоге с губернатором
  When я закрываю диалог
  Then маршрут в системе НЕ строится
  And первый клик после закрытия не воспринимается как навигация
```

## Гипотеза причины и направление фикеса
- Глобальный `onPointerDown` сцены (`SpaceFlightScene`/`StarMapScene`) ловит
  клик, который должен был «съесть» модалка/диалог. Вероятные причины:
  - у фонов/кнопок модалки нет `event.stopPropagation()` (Rule 2), либо
  - событие приходит уже после закрытия оверлея/перехода сцены (тот же
    pointerup/down «протекает» в новый обработчик).
- **Направление**:
  1. На фоне и кнопках модалок/диалогов — `eventMode='static'` + явный
     `stopPropagation` (см. как сделано в `NpcContactPanel`).
  2. Гард в глобальном `onPointerDown`: игнорировать первый клик в течение
     короткого окна после закрытия модалки/перехода сцены, либо проверять, что
     цель события не принадлежит оверлею.
