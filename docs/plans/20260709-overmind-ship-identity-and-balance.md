# Overmind Ship Identity & Ship-Speed Balance

## Overview

Five related requests bundled together at planning time (ship balance + Overmind identity):

1. **Rename the per-ship "Доминатор" name** — replace with "Жнец" (Reaper) everywhere it appears as a display string.
2. **Give Overmind ships a genuinely distinct combat identity**: their own `NpcRole.OVERMIND` (not borrowed `PATROL` stats/art/loadout), plus multiple size tiers (small/medium/large/boss) with visually distinct hull art per tier.
3. **Scale research-substance ("artifact") drops by ship significance** — bigger Overmind hulls drop more/better loot for research-station upgrades.
4. **Retune ship speed** so the best available engine is ~2× starter speed (currently 2.36×), and gate that top engine behind an explicit day so it becomes available around year 3 rather than the current natural tech-climb (which can reach it in well under a year).
5. **(Discovered while tracing the rename, opted into by request)** Unify four inconsistent surfaces that all claim to show the Overmind faction's display label — three duplicate hardcoded "Сверхразум" dicts plus a fourth, contact-panel-only "Предтечи"/"Precursors" that disagrees with the other three.

### Ship speed retune + gating (item 4)
- Speed is **derived**, not a per-item field: `spd = (0.05 + e.techLevel * 0.03) * m` (`src/systems/equipment/ShipLoadout.ts:547`, `m` = micromodule multiplier). Starter `eq_engine_i` (techLevel 2) → 0.11 px/ms; top `eq_engine_v` (techLevel 7) → 0.26 px/ms — a **2.36× ratio**. To hit **exactly 2×** while keeping the starter speed unchanged (0.11) and the top engine's `techLevel: 7` unchanged (so its *tech-gating* tier is untouched), the formula's coefficients need retuning, not any single item's field: solving `2a + b = 0.11` and `7a + b = 0.22` gives `a = 0.022, b = 0.066` → new formula `spd = (0.066 + e.techLevel * 0.022) * m`. This changes cruise speed for **every** engine tier proportionally (mid-tier `eq_engine_iii`, techLevel 5, moves from 0.20 → 0.176) — acceptable and in the spirit of "not many times faster than each other," but flag it explicitly since it's a formula-level change, not an isolated item edit.
- Verify against existing balance comments: `GearCatalog.ts:365-368`'s comment ties `eq_engine_v`'s speed to "finally out-running the interceptor tier (`npcSpeed` 0.2)" — new top speed 0.22 still clears that bar (barely); confirm this against `playtest-traps.md`'s "Combat Maneuver Conventions" table (basic NPC 0.08, interceptor/OVERMIND/PIRATE 0.2) as part of this task, since Overmind ship speed also comes from `ROLE_STATS[NpcRole.PATROL].speed = 0.10` today and may itself need revisiting once `NpcRole.OVERMIND` (item 2) gets its own entry — cross-reference, don't tune in isolation.
- **Calendar gating is genuinely absent today, and the natural tech climb is fast, not slow**: `advanceTech()` (`src/systems/GalaxySimulator.ts:608-636`) advances **every** non-hostile system's `techLevel` by +1 every `TECH_ADVANCE_INTERVAL_RESEARCH_LAB=50` days (with a lab) or `TECH_ADVANCE_INTERVAL_PLAIN=100` days (flat, `GalaxySimulator.ts:600-602`), **regardless of starting tech level** — a system generated at the tech-5 floor (`GALAXY_MAX_TECH_FLOOR`) with a research lab reaches tech-7 in as little as ~100 days. On top of that, `ShopGenerator.generateShop()` (`src/systems/equipment/ShopGenerator.ts:54-58,74-79`) independently rolls per-shop-per-week stock chance (`stockChance`: tech-7 ≈ 0.35, halved again to ≈0.175 for `isRareGear` items like `eq_engine_v` via `RARE_STOCK_FACTOR=0.5`) — a probabilistic *availability* filter, not a *day* filter. Neither mechanism is calendar-explicit, and both are shared by every other tech-gated item (weapons, hulls), so slowing them broadly to hit "year 3" for one engine would also delay every other tech-7/8 item galaxy-wide — **explicitly out of scope** (user decision: gate this engine only).
- **Explicit user decision**: add a new, opt-in `minDay?: number` field to the gear catalog (mirrors the existing `rare?: boolean` flag pattern, `GearCatalog.ts:61-67`), consumed only by `ShopGenerator` as an additional stocking gate alongside `maxTechLevel`, applied only to `eq_engine_v`. This is additive/optional — no schema/migration impact on `GearListing`/shop generation for every other item, which simply never sets the field.
